## TEST-04 상세

### 앱 현재 설정 (Tesseract.js, 1800px, 대비 늘리기)
| 영수증 | 정답 | 앱 결과 |
|---|---|---|
| 001 | 2026-11-11 / 110,200 | 빈칸 / 빈칸 |
| 002 | 2026-11-11 / 229,000 | 빈칸 / 빈칸 |

인식 원문이 대부분 깨짐 (예: "구매 2026-11-11 12:49" 줄 → `Ein oo -11- § das 12:49`).

### 개선 시도 (Tesseract.js 전처리·설정 바꾸기)
해상도(1800~4000px), 흑백 방식(대비/적응형 흑백), 가로선 제거, 페이지 분석 방식(psm 3/4/6), 언어(kor+eng / kor) 조합 약 20가지.
**어떤 조합도 두 영수증의 일자·금액을 모두 맞히지 못했고, 조합마다 결과가 불안정했다.** 가장 나은 조합도 금액 1~2개, 일자 0~1개.

### 비교: macOS 내장 Apple Vision
같은 사진에서 일자·금액 줄을 정확히 읽음 (장당 0.3~0.7초). 예: `구매 2026-11-11 12:00`, `합 / 계 / 229,000`, `카드결제액 / 229,000`.
- 차이점 1: 칸 단위로 결과가 나와 "합계"와 금액이 다른 줄로 분리됨 → 위치(좌표)로 같은 줄을 다시 묶어야 현재 파서가 쓸 수 있음
- 차이점 2: 001은 `2026-11-1171:49`처럼 날짜와 시간이 붙어 나옴 → 파서 보완 필요
- 현재 파서에 없는 키워드: `구매`(일자), `카드결제액`(금액) → 추가 필요

### 판단
- Tesseract.js로는 실제 영수증 자동 인식 목표(70%)를 달성하기 어렵다. ([[ADR-0002-OCR-엔진-Tesseract-js]]에서 예상한 위험이 현실화)
- 기기 내장 엔진(맥: Apple Vision, 안드로이드: ML Kit)은 정확도가 훨씬 높다. ML Kit는 아직 실제로 시험하지 않았다.
- 자동 인식이 실패해도 앱 자체는 동작한다(빈칸 → 직접 입력). 이는 요구사항(인식 실패 시 빈칸)과는 맞지만, 앱의 핵심 가치인 자동 입력은 거의 되지 않는다.
- 엔진을 바꾸는 것은 설계 변경이므로 사용자 결정이 필요하다.
