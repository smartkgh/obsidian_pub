# 오프라인 DOCX·PDF 생성

## 요약
DOCX와 PDF 모두 서버 없이 기기(브라우저) 안에서 만들 수 있다.
가장 중요한 문제는 **한글 폰트**다. PDF는 폰트를 파일 안에 넣어야 어느 기기에서 열어도 깨지지 않는다.

## DOCX (REQ-011)
- **docx (npm)**: 브라우저와 Node 모두에서 동작. 표, 셀 병합, 테두리, 음영, 이미지, 페이지 나누기 지원. `Packer.toBlob()`으로 파일을 만들어 다운로드.
- 원본 양식의 표(머리글, 내역 표, 송금처/서명/예산 영역, 회색 칸)를 표 셀 병합과 음영으로 재현할 수 있다.
- 폰트는 이름만 지정(예: 맑은 고딕, 나눔고딕)하고, 실제 표시는 문서를 여는 기기의 폰트를 따른다.

## PDF (REQ-012)

| 방법 | 설명 | 장점 | 단점 |
|---|---|---|---|
| **pdf-lib + 한글 폰트 내장** | 좌표로 선과 글자를 직접 그림 | 모양을 정확히 제어, 폰트 내장으로 깨짐 없음 | 레이아웃 코드를 직접 작성, 폰트 파일 수 MB |
| jsPDF + 한글 폰트 | pdf-lib와 비슷 | 예제가 많음 | 한글 폰트 등록이 번거로움 |
| HTML → 브라우저 인쇄(PDF로 저장) | 화면용 HTML을 A4로 인쇄 | 구현 쉬움 | 기기마다 결과가 다름, 자동 저장이 아니라 인쇄 창을 거침 |

- 한글 폰트: Noto Sans KR, 나눔고딕 등 **OFL 라이선스** 폰트를 앱에 포함하면 오프라인에서 사용 가능. 필요한 글자만 남기는 서브셋으로 크기를 줄일 수 있다.

## 영수증 증빙 페이지 (REQ-013)
- DOCX, PDF 모두 2페이지부터 이미지 삽입 가능.
- 폰 사진은 크기가 커서(수 MB) 출력 전에 해상도를 줄여야 파일이 가벼워진다.

## 이 프로젝트와의 관련성
- 관련 요구사항: REQ-010, REQ-011, REQ-012, REQ-013
- 시사점: 결의서 레이아웃을 **하나의 데이터 구조**(칸 위치, 크기)로 정의하고 DOCX와 PDF가 같은 정의를 쓰게 하면 두 출력물의 모양이 일치한다.
