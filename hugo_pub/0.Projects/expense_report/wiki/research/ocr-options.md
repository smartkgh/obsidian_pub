# 오프라인 영수증 OCR 선택지

## 요약
안드로이드와 맥북에서 인터넷 없이 영수증 글자를 읽을 수 있는 방법은 세 가지다.
정확도는 플랫폼 내장 엔진(ML Kit, Apple Vision)이 좋고, 코드 하나로 두 기기를 다 지원하려면 Tesseract.js가 쉽다.
v1에서 필요한 값은 **숫자(일자, 금액)뿐**이라 한국어 인식 품질보다 숫자 인식 품질이 더 중요하다.

## 비교

| 엔진 | 동작 위치 | 한국어 | 오프라인 | 장점 | 단점 |
|---|---|---|---|---|---|
| **Google ML Kit v2** (번들 모델) | 안드로이드 앱 안 | 지원 (`text-recognition-korean`) | 가능 — 모델이 앱에 포함 | 사진 인식 정확도 높음, 빠름 | 안드로이드 앱(APK)으로 만들어야 함, 앱 크기 약 4MB 증가 |
| **Apple Vision** | macOS 앱 안 | 최신 OS에서 지원 (실행 중 확인 필요) | 가능 | 맥 내장, 정확도 높음 | Swift 네이티브 코드 필요, OS 버전에 따라 한국어 지원 다름 |
| **Tesseract.js** | 브라우저 안 (WebAssembly) | 지원 (`kor.traineddata`) | 가능 — 파일을 로컬에 두면 | 웹 코드 하나로 안드로이드·맥 모두 동작 | 사진(기울기, 조명)에 약함, 언어 파일 수 MB, 경로 설정 실수 시 오프라인 실패 |

## 이 프로젝트와의 관련성
- 관련 요구사항: REQ-002(일자), REQ-003(금액), REQ-014(로컬 전용), REQ-015(안드로이드), REQ-016(맥북)
- 시사점:
  - 인식 대상이 숫자와 몇 개의 키워드("승인", "합계" 등)라서 Tesseract.js도 쓸 만할 가능성이 있다. 실제 영수증 사진으로 검증이 필요하다.
  - 안드로이드에서 정확도를 우선하면 ML Kit, 개발 단순성을 우선하면 Tesseract.js.
  - 맥북은 사진이 보통 폰에서 옮겨 온 파일이고 화면이 커서 수정이 쉬우므로 Tesseract.js로 충분할 가능성이 높다.
  - 어떤 엔진이든 인식 실패 시 빈칸으로 두고 사용자가 고치는 흐름(REQ-004)이 있어 정확도 부담이 줄어든다.

## 의문점
- 실제 카드 영수증 사진에서 Tesseract.js의 숫자 인식률 → 검증 단계에서 샘플로 측정 필요
- Apple Vision의 한국어 지원 macOS 최소 버전 → 공식 표 없음
