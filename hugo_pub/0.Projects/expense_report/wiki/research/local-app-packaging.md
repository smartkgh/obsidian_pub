# 안드로이드·맥북 로컬 앱 형태

## 요약
"로컬 전용"을 만족하면서 안드로이드와 맥북 둘 다 지원하는 앱 형태는 세 가지다.
화면, 입력, 문서 생성은 **웹 기술로 한 번만** 만들고, 기기별로 감싸는 방식이 가장 효율적이다.

## 비교

| 형태 | 안드로이드 | 맥북 | 사용할 OCR | 장점 | 단점 |
|---|---|---|---|---|---|
| **A. 웹앱(PWA)** | 크롬에서 "홈 화면에 추가" 후 오프라인 사용 | 브라우저에서 사용 | Tesseract.js | 코드 하나, 설치 쉬움 | 폰에 설치하려면 앱을 **HTTPS 주소에서 한 번 받아야 함**(데이터는 전송 안 됨). OCR 정확도 상대적으로 낮음 |
| **B. 웹 + 안드로이드 앱 포장(Capacitor)** | APK 파일로 직접 설치, 완전 오프라인 | 같은 웹 코드를 맥에서 로컬 실행(localhost) | 안드로이드: ML Kit / 맥: Tesseract.js | 폰에서 정확도 높고 인터넷 주소 필요 없음. 화면·문서 코드는 공유 | 안드로이드 빌드 도구(Android Studio) 필요, OCR 코드가 두 갈래 |
| C. 기기별 네이티브 앱 | Kotlin + ML Kit | Swift + Vision | 각 플랫폼 내장 | 정확도·성능 최고 | 코드 두 벌, 문서 생성도 두 번 구현 |

## "로컬 전용"의 의미 정리 (REQ-014)
- 영수증 이미지, 입력 내용, 출력 파일은 **기기 밖으로 나가지 않는다**. 세 형태 모두 만족한다.
- 차이는 **앱 자체를 어떻게 설치하느냐**다.
  - A: 앱 파일(코드)을 처음 한 번 인터넷 주소(예: GitHub Pages)에서 받는다. 이후 오프라인 동작.
  - B, C: 앱 파일을 직접 기기에 설치한다. 인터넷 주소가 필요 없다.
- 브라우저의 오프라인 기능(서비스 워커)은 `https://` 주소나 `localhost`에서만 동작한다. 맥에서 띄운 `http://192.168.x.x` 주소를 폰에서 여는 방식은 오프라인 설치가 안 된다.

## 저장 (REQ-017)
- 웹 기술이라면 IndexedDB에 작성 중인 결의서와 영수증 이미지를 저장할 수 있다. 기기 안에만 저장된다.

## 이 프로젝트와의 관련성
- 관련 요구사항: REQ-014, REQ-015, REQ-016, REQ-017
- 시사점: A와 B는 화면·문서 생성 코드를 공유하므로, **A로 시작해서 OCR 정확도가 부족하면 B로 넘어가는 경로**가 가능하다. 설계 단계에서 OCR 부분을 교체 가능한 모듈로 분리하면 된다.

## 의문점
- 앱 코드를 인터넷 주소(GitHub Pages 등)에 올리는 것이 "로컬 전용" 요구에 맞는지 → 사용자 결정 필요
